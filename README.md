# ReconPilot — AI Finance Controller

ReconPilot is a submission-ready prototype for reconciling **invoices → payments → settlements → bank transactions**. It combines deterministic financial controls with constrained AI investigation while remaining **fail-closed**: an LLM can recommend a candidate, but deterministic validation is required before an automatic match is persisted.

## Core architecture

```text
Input batch
   ↓
Schema validation
   ↓
Invoice → Payment
   ↓
Payment → Settlement
   ↓
Settlement → Bank
   ↓
Unique deterministic match?
   ├── YES → AUTO RESOLVE
   └── NO
         ↓
Candidate generation
         ↓
AI investigation (optional)
         ↓
Deterministic safety validation
         ↓
Decision gate
      ├── AI RESOLVE
      ├── SUGGEST
      └── EXCEPTION
```

### Non-negotiable safety invariant

> **LLM confidence can never independently create an auto-match.**

For an AI auto-resolution, the selected transaction must be one of the deterministic candidates, must exist in the source batch, and must independently pass settlement → bank validation. Invalid AI output becomes a safety exception instead of a match.

## AI execution modes

| Mode | Meaning | External API |
|---|---|---|
| `local` | Reproducible deterministic local evaluator used for offline benchmark/demo | No |
| `live` | Real LiteLLM/provider investigation | Yes |
| `off` | Disable AI; ambiguous cases abstain safely | No |

The local evaluator is **never labeled as an LLM** in the benchmark or UI.

## Benchmark

The included synthetic benchmark has 104 cases across 10 controlled scenarios:

- exact match — 20
- fee-adjusted match — 15
- delayed settlement — 10
- fuzzy reference — 10
- duplicate candidate — 10
- partial payment — 8
- missing counterparty — 8
- corrupt record — 5
- no valid match — 8
- ambiguous match — 10

Run the reproducible benchmark:

```bash
python -m reconpilot benchmark --seed 42 --mode local
```

Run five seeds:

```bash
python -m reconpilot benchmark --seeds 42 43 44 45 46 --mode local
```

Reports are written to `benchmark/`:

```text
run_seed_42.json
metrics.json
scenario_metrics.json
exceptions.json
multi_seed_summary.json
```

### Benchmark results from the packaged build

On seed 42, the local evaluator produced **75/104 resolved cases (72.12%)**, **100% resolved-match accuracy**, and **0 false auto-matches**. The deterministic baseline resolved 11/104 under its conservative 3-day date-window policy. These are synthetic benchmark results, not production claims.

Across seeds 42–46, resolution and resolved accuracy were stable because the scenario counts are fixed; measured throughput varied with local runtime. The multi-seed summary is generated by the benchmark command rather than hard-coded into the application.

## Metrics

ReconPilot reports:

- resolution / coverage rate
- resolved-match accuracy
- overall accuracy
- false automatic matches
- deterministic vs AI-assisted resolutions
- suggested matches
- exception taxonomy
- throughput
- scenario-level resolution
- candidate Recall@1 and Recall@3
- AI contribution rate

The benchmark compares the controller against a deterministic baseline on the **same generated dataset**.

## Exception taxonomy

Operational failures are separated from malformed records and reconciliation ambiguity:

- `INVALID_RECORD`
- `MISSING_RECORD`
- `NO_CANDIDATES`
- `AMBIGUOUS_MATCH`
- `AI_UNAVAILABLE`
- `AI_DISABLED`
- `AI_EXCEPTION`
- `AI_SAFETY_BLOCK`
- `AI_SUGGESTION_REQUIRES_REVIEW`
- `PIPELINE_FAILURE`

Malformed numeric values such as `NOT_A_NUMBER` are classified as `INVALID_RECORD`, not silently treated as matches.

## Auditability

Every case records stage/action/decision/reason/confidence and candidate IDs. AI-assisted cases additionally persist:

- AI mode
- classification
- selected candidate
- evidence
- uncertainty

The UI exposes the complete case lifecycle and audit trail.

## Deployment

A Dockerfile and `render.yaml` are included for a lightweight Streamlit deployment. The default deployment configuration uses `local` mode so the public demo does not depend on a secret API key. For real provider-backed investigation, configure the provider/model and secret in the deployment environment rather than committing credentials.

## Security

- `.env` is ignored and is not included in the submission package.
- SQLite databases are ignored from source control.
- No API key is stored in the repository.
- AI receives only the target record plus deterministic candidates, not the full database.
- Invalid AI output cannot crash the batch or create an automatic match.
